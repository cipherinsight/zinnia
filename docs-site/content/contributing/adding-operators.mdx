# Adding Operators

An *operator* here is anything a circuit calls or applies: a Python operator (`+`, `<`, `@`), a builtin (`len`, `sum`), a NumPy function (`np.sort`), or a method (`a.reshape(...)`, `lst.append(x)`). This guide shows where each kind is dispatched and what to change to add one.

## How a Call Is Dispatched

Python operators go through `IRGenerator::visit_binary_op` and `apply_unary_op` (`src/ir_gen/visitors.rs`) to `helpers::value_ops::apply_binary_op`, which dispatches on the operand values: scalars, complex numbers, static arrays, dynamic arrays, lists and tuples.

Calls go through `visit_named_attr` in `src/ir_gen/named_attr/mod.rs`. It evaluates the arguments, then tries the dispatchers in this order and takes the first that answers:

1. `try_builtin` (`builtins.rs`): calls without a receiver, such as `len`, `range`, `zip`, `sum`, `min`;
2. `try_numpy_func` (`numpy_funcs.rs`): explicit `("np", name)` arms for NumPy functions;
3. `try_list_method` (`list_methods.rs`): methods of lists;
4. `try_ndarray_method` (`ndarray_methods.rs` and the `*_compat.rs` files): array methods and properties;
5. `try_np_fallback` (`numpy_funcs.rs`): `np.*`, `math.*` and `zinnia.*` calls built by name through `ops::registry::build_op`;
6. a registered `@zk_chip` or `@zk_external` function of that name.

A call that none of them answers is a compile error. After an `np.*` call is built, `finish_numpy_call` converts list results of array-returning functions into arrays (the `returns_one_ndarray` list), records views and read-only results, and writes into an `out=` argument.

The implementations themselves live in `src/helpers/` (array semantics: indexing, assignment, broadcasting, reductions, shapes, dtype conversion) and `src/ops/` (the scalar NumPy functions in `np_like/`, static-array operations in `static_ndarray_ops/`, dynamic-array operations in `dyn_ndarray/`).

## Adding an Element-Wise NumPy Function

A function that applies a scalar operation to each element, such as `np.sign`, is the simplest case. It needs a scalar implementation, and `try_np_fallback` applies it to every element of an array argument.

1. **Implement `Op`.** Create `src/ops/np_like/np_<name>.rs` with a type implementing `ops::Op`. A unary function reads its argument as `"x"`, a binary one as `"x1"` and `"x2"`. `np.sign` is a complete example:

   ```rust
   use crate::builder::IRBuilder;
   use crate::ops::{Op, OpArgs};
   use crate::types::Value;

   pub struct NpSignOp;

   impl Op for NpSignOp {
       fn build(&self, builder: &mut IRBuilder, args: &OpArgs) -> Value {
           let x = args.require("x");
           match x {
               Value::Integer(_) | Value::Boolean(_) => builder.ir_sign_i(x),
               Value::Float(_) => builder.ir_sign_f(x),
               _ => panic!("np.sign: unsupported type {:?}", x.zinnia_type()),
           }
       }
   }
   ```

   The macros at the top of `src/ops/np_like/mod.rs` (`define_np_unary_math`, `define_np_binary_math`, `define_np_compare`, `define_np_arith`, `define_np_minmax`) generate the common shapes, for example `define_np_unary_math!(NpSqrtOp, "sqrt", "np.sqrt", ir_sqrt_f);`.
2. **Export it** with `pub mod np_<name>;` and `pub use np_<name>::Np<Name>Op;` in `src/ops/np_like/mod.rs`.
3. **Register the name** with an arm in `build_np_op` in `src/ops/registry.rs`, for example `"sign" => np_like::NpSignOp.build(builder, args),`.
4. **Check the array cases.** `try_np_fallback` maps a unary function over lists, static arrays and dynamic arrays. A binary function reaches `apply_binary_op`, with broadcasting, only when its name is in the `binary_apply_name` table of `try_np_fallback`. Otherwise both arguments must be scalars. If NumPy's function accepts a positional `out` argument, its name belongs in `ufunc_input_count` (`src/ir_gen/named_attr/mod.rs`).

## Adding Other Functions and Methods

Functions that are not element-wise (reductions, reshaping, sorting, indexing helpers) and methods are written directly against the values:

1. Add an arm to the matching dispatcher, `("np", "<name>") => ...` in `try_numpy_func`, a method name in `try_ndarray_method` or `try_list_method`, or a name in `try_builtin`.
2. Implement the operation in `src/helpers/` or `src/ops/` as a function of the `IRBuilder` and the argument values. Handle the value kinds the function accepts: `Value::StaticArray` (fixed shape, cells in a storage), `Value::DynamicNDArray` (runtime shape within an envelope), and Python lists and tuples. `src/helpers/array_ops/` has entry points that already handle static and dynamic arrays together.
3. If the function returns one array, add its name to `returns_one_ndarray`. If NumPy returns a view, add it to `RETURNS_A_VIEW`.
4. Add the function to the user documentation in `docs-site/content/programming-guide/numpy-api.mdx`.

Follow these rules when emitting IR:

- **Build values through `IRBuilder`.** Use the `ir_*` methods (`ir_add_i`, `ir_mul_f`, `ir_select_i`, `ir_less_than_i`, ...), which fold compile-time constants as they go. Compute a result in Rust only when every input is a compile-time constant (`Value::int_val()`, `float_val()`).
- **Read and write arrays through the store.** Use the helpers in `src/helpers/static_array/` and `src/helpers/array_ops/` instead of building `ArrayRead`/`ArrayWrite` yourself. They apply the write predicate, so a write in a branch that is not taken changes nothing, and they emit the index checks.
- **Emit checks through `src/builder/guard.rs`** (`ir_assert`, `ir_assert_u128_lt`, ...). They hold only where the code runs, so a check in an untaken branch cannot make the circuit unsatisfiable.
- **Reject what you do not support.** A `panic!` with a message naming the function and the unsupported case becomes a compile error for the user. Never return a value that differs from NumPy's.
- **Ask, do not assume.** When a cheaper lowering needs a fact (an index in range, a non-negative value), ask the builder's bound and fact queries, and fall back to the general lowering when the answer is not "proved".

## Adding an IR Instruction

Most operators need no new instruction. When one is needed:

1. Add the variant to `IR` in `src/ir_defs.rs`, with its cases in `signature`, `class_name` and `import_from`, in `export_data` if it has parameters, and in `is_fixed` if dead-code elimination must keep it.
2. Give it a value in `build_value` (`src/builder.rs`): its result type, and its compile-time value when the operands are constants. Add a typed `ir_*` method to `IRBuilder`.
3. Define its semantics in the kernel (`src/prove/kernel.rs`) and evaluate it in preprocessing (`src/prove/preprocess/mod.rs`).
4. Add a method to the `Synthesizer` trait (`src/prove/traits.rs`), its case in `interpret_ir` (`src/prove/interpreter.rs`), and implementations for the mock, halo2-base and Noir synthesizers. Each implementation must accept exactly the values the kernel defines.

Most `match` statements over `IR` have no wildcard arm, so `cargo check --features halo2-base-backend,noir-backend` lists the places that still need a case. The range analysis (`src/optim/range.rs`) and the SMT encoding (`src/optim/smt_encoding.rs`) treat an unknown instruction as an unconstrained value. Add a case there if the optimizer should reason about the new one.

## Adding an Array Operator with Lowering Choices

An operator whose best circuit depends on the target or on which outputs are used (like `np.sort`) is emitted as `ArrayOp` placeholders, one per output element, and lowered by constructions in `src/lower/`. This needs an `OpKind` in `src/lower/op.rs`, a frontend function that emits the lanes, and at least one `Construction` with its preconditions, postconditions, cost on each target and soundness argument, registered in `lower::registry`. The module documentation of `src/lower/mod.rs` and the existing families (`sort/`, `gather/`, `scatter/`, `linear/`) are the reference.

## Testing

Add Python tests next to the existing ones for the same kind of operator: `testing/operator/ndarray/` for array functions and methods, `testing/operator/nocls/` for builtins, `testing/operator/lst/` for list methods. Compare with NumPy on several inputs, including negative values and indices, empty and single-element arrays, inputs that reach the edges of the documented range, and calls inside a branch whose condition is a private value. Check that unsupported cases fail at compile time with a clear message.
