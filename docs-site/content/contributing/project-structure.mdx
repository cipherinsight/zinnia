# Project Structure

## Top-Level Layout

| Path | Contents |
|---|---|
| `zinnia/` | the Python package: user API, source lowering, AST transformer, input parsing |
| `src/` | the Rust core, built as the extension module `zinnia._zinnia_core` |
| `Cargo.toml`, `build.rs`, `pyproject.toml` | the Rust crate and the maturin build; the Cargo features `halo2-base-backend` and `noir-backend` select the proving backends |
| `testing/` | the Python test suite (pytest) |
| `tests/` | Rust integration tests (the Noir backend) |
| `examples/` | small runnable circuits |
| `scripts/` | `develop.sh` (editable build), `check_tests_compile.sh`, `check_build_matrix.sh` |
| `tools/` | `fuzz_differential.py`, a differential fuzzer with NumPy as the oracle |
| `docs/` | design notes on arrays (`array-ssa.md`), array facts (`array-facts.md`, `array-facts-lowering.md`), helper functions (`helpers.md`) and the measurement switches (`ablations.md`) |
| `docs-site/` | this documentation site |
| `benchmarking/` | benchmark programs, handwritten baselines, the harness, and the Noir fixed-point library `noir_fpc` that the Noir backend embeds |
| `eval/`, `studies/` | evaluation data and user-study material |

## The Python Package `zinnia/`

| Directory | Contents |
|---|---|
| `__init__.py` | the public names: types (`Integer`, `Float`, `Complex`, `NDArray`, `DynamicNDArray`, ...), `Public`/`Private`, `zk_circuit`, `zk_chip`, `zk_external`, `requires`, `ZKCircuit`, `ZKCompiledProgram`, `ZinniaConfig` |
| `api/` | `ZKCircuit` and `@zk_circuit` (`zk_circuit.py`), chips (`zk_chip.py`), external functions (`zk_external_func.py`), the compiled program with `prove`, `verify`, key management and serialization (`zk_compiled_program.py`) |
| `compile/zinnia_compiler.py` | `ZinniaCompiler`: lowers and translates the source, builds the JSON payloads and calls the core |
| `compile/lowering/` | source rewrites before translation: imports, module constants, nested functions and lambdas as generated chips, callbacks such as `map` and `np.vectorize`, `zip`/`reversed` loops |
| `compile/transformer/` | translation of Python's `ast` into the AST dictionary the core reads: `base.py` (shared visitor and type annotations), `circuit.py`, `chip.py`, `external_func.py`, `_precondition.py` (`requires` preconditions) |
| `compile/_bridge.py` | the functions imported from `zinnia._zinnia_core` |
| `lang/` | the annotation types (`type.py`), `Public`/`Private` (`typing.py`), Poseidon helpers (`operator.py`, `poseidon_params.py`) |
| `spec/` | the `requires` decorator and the predicate names it accepts |
| `exec/` | conversion of Python arguments into the circuit's input tree (`input_parser.py`) and result wrappers |
| `config/` | `ZinniaConfig` (backend target, `loop_limit`, `recursion_limit`, `enable_memory_consistency`) and `OptimizationConfig` (pass switches) |
| `debug/` | exceptions with source locations and their formatting |
| `internal/` | small internal objects for chips, external functions and array values |

## The Rust Core `src/`

| Path | Contents |
|---|---|
| `lib.rs` | the Python entry points (`compile_circuit`, `prove_circuit`, `verify_proof_artifact`, IR export and import) and the pass pipeline |
| `ast/` | the AST types, deserialized from the transformer's dictionary |
| `ir_gen/` | the IR generator: statement visitors (`visitors.rs`), loops (`iteration.rs`), chip and external calls (`chip_external.rs`), call dispatch (`named_attr/`), inputs and their domain checks (`helpers.rs`, `input_domain.rs`), preconditions, outputs and the public layout (`outputs.rs`), aliasing rules (`detached_copies.rs`, `list_sharing.rs`) |
| `builder.rs`, `builder/` | `IRBuilder`: statement creation with compile-time folding, the array store (`store.rs`, `arrays.rs`, `stale.rs`), checks under the execution predicate (`guard.rs`), array facts and bound queries |
| `helpers/` | the implementations of array semantics: indexing and assignment (`array_ops/`), static-array operations (`static_array/`), broadcasting, dtype conversion, binary operations and selects on values (`value_ops.rs`) |
| `ops/` | operator implementations: the scalar NumPy functions (`np_like/`, built by name in `registry.rs`), static-array operations (`static_ndarray_ops/`), dynamic-array operations (`dyn_ndarray/`) |
| `scope.rs`, `ir_ctx.rs` | scopes and the context of the IR generator |
| `types/` | `ZinniaType`, `Value`, scalar and composite values, shapes and envelopes |
| `ir.rs`, `ir_defs.rs`, `ir_array.rs` | the IR: statements and graph, the instruction enum, array accesses |
| `optim/` | the IR passes, constant resolution (`resolver/`, `range.rs`, `smt_encoding.rs`, `z3_budget.rs`), preconditions and facts (`predicates/`, `array_facts/`) |
| `lower/` | the array lowering layer and its construction families (`sort/`, `gather/`, `memory/`, `scatter/`, `linear/`, `stats/`, `permutation.rs`) |
| `prove/` | the backends: kernel, interpreter, preprocessing, `mock/`, `halo2_base/`, `noir/` |
| `circuit_input.rs` | the input tree passed from Python and the resolved witness |
| `provenance.rs` | the provenance table: structural records from IR generation for passes and backends |

## Test Suite

| Directory | Contents |
|---|---|
| `testing/api/` | the Python API: compilation, configuration, inputs, chips, external functions, mock execution |
| `testing/syntax/` | Python constructs: assignments, `if`, `for`, `while`, comprehensions, unpacking, subscripts |
| `testing/operator/` | builtins and methods by receiver: `ndarray/`, `lst/`, `tupl/`, `nocls/` (global functions), `np_like/` |
| `testing/lang/` | language semantics, array semantics, soundness checks, and agreement between backends |
| `testing/semantics/array/` | array operator cases generated from `operators.yaml`, each with its expected status |
