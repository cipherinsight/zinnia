# Optimization Passes

After IR generation, `compile_circuit_impl` in `src/lib.rs` builds a list of pass names and `run_pass_pipeline` applies them one after another. Each pass implements the `IRPass` trait of `src/optim/mod.rs`:

```rust
pub trait IRPass {
    fn exec(&self, ir_graph: IRGraph) -> IRGraph;
}
```

Most passes live in `src/optim/`. The array lowering layer and the passes tied to it live in `src/lower/`.

## The Soundness Rule

A pass may change how a value is computed. It must not change which inputs the circuit accepts or which outputs it proves. In particular, a pass may drop a check only when the check holds on every input that satisfies the remaining constraints, and that argument may not rest on the check itself or on another check dropped with it. Facts used to simplify must come from the statements (constants, intervals, gadget postconditions, the program's checks that stay). Witness values are never a source. An answer of "unknown" from the resolver or Z3 is treated as "no information".

## The Pipeline

The passes run in this order. A pass marked with a switch of `OptimizationConfig` (`zinnia/config/optimization_config.py`) runs only when the switch is on. All switches default to on.

| # | Pass | Switch |
|---|---|---|
| 1 | `PatternMatchOptim`, `DoubleNotElimination` | `shortcut_optimization` |
| 2 | `AssertedEqualityConstantPropagation`, `ConstantFold` | `constant_fold` |
| 3 | `DeadCodeElimination` | `dead_code_elimination` |
| 4 | `AlwaysSatisfiedElimination` | `always_satisfied_elimination` |
| 5 | `DuplicateCodeElimination`, `SelectChainForwarding`, then `ConstantFold` and `DeadCodeElimination` again when those switches are on | `duplicate_code_elimination` |
| 6 | `SortCountQueries`, `ArgmaxQueries`, `ConstantTableReads` | always |
| 7 | `ArrayLowering` | always |
| 8 | `PredicatedSimplification`, `DeadCodeElimination`, `SelectMerge`, `DeadCodeElimination` | always |
| 9 | `ConstantSelectorQueries`, `NeutralNegation` | `shortcut_optimization` |
| 10 | `DuplicateCodeElimination`, `SelectChainForwarding`, `DeadCodeElimination` | `duplicate_code_elimination` |
| 11 | `AssertSubsumption` | always |
| 12 | `DynamicNDArrayMetaAssertInjection` | see below |
| 13 | removal of the domain checks of unread inputs, then `DeadCodeElimination` and `CheckedAbsSquare` (the last one under `shortcut_optimization`) | always |

The measurement switch `ZINNIA_ABLATE_CHECK_ELIM=1` (`docs/ablations.md`) leaves out passes 4 and 11, the two that drop program checks.

## Passes Before Array Lowering

**`PatternMatchOptim`** (`pattern_match_optim.rs`) rebuilds the graph and applies local rewrites: `and`/`or` with a constant operand, selects with a constant condition, with equal branches, or with constant Boolean branches (`select(c, true, false)` is `c`), `x + 0`, `x - 0`, `x - x`, `x * 1`, `x / 1`, comparisons of a value with itself, and the canonical form of ordering comparisons (`a > b` becomes `b < a`, `a >= b` becomes `not (a < b)`), so that complementary comparisons become one statement after duplicate elimination. Rewrites that would remove a hidden check, such as the quotient window of a float division, are not applied.

**`DoubleNotElimination`** replaces `not (not x)` by `x`.

**`AssertedEqualityConstantPropagation`** finds assertions of the form `x == k` for a constant `k` and lets the statements that read `x` read `k`. The assertion itself stays.

**`ConstantFold`** rebuilds the graph through a fresh `IRBuilder`, replacing every operand whose value the builder knows by a shared constant statement. The builder computes the value of every statement whose operands are all constant, so these statements are replaced by constants in turn and the original computations become dead.

**`DeadCodeElimination`** keeps the fixed statements (`IR::is_fixed`) and everything they depend on, and removes the rest. An `ArrayFact` keeps none of its operands alive, and is kept exactly while all of them are.

**`AlwaysSatisfiedElimination`** removes an `Assert` whose condition is a constant true, or that range analysis or Z3 proves true from the statements that define it, without assuming any other check of the program. An assertion proved false is a compile error. The input domain checks are not examined.

**`DuplicateCodeElimination`** merges statements with the same instruction (parameters included) and the same operands, in one forward walk, so merged producers make their consumers equal in turn.

**`SelectChainForwarding`** resolves a read after a write at the same runtime index. A write `a[i] = w` over known cells and a read `a[i]` become a chain of selects on `i == k`, and when the circuit asserts `i < n` the chain is `w`.

**`SortCountQueries`**, **`ArgmaxQueries`** and **`ConstantTableReads`** (`src/lower/sort/`) rewrite three patterns before array lowering, so that the array values they no longer read are not lowered: a comparison with a sorted value is answered from a count of the same sort, `h[argmax(h)]` is answered as `any(h)`, and a read of a constant affine table at a runtime index is computed in closed form.

## Array Lowering

**`ArrayLowering`** (`src/lower/emit.rs`) replaces every `ArrayOp` placeholder and every array version with real constructions. It runs after dead-code elimination, so it sees only the outputs the program uses, and it chooses constructions by their cost on the compile target. No backend accepts its input, which is why it is not behind a switch. [Arrays and Memory](/docs/compiler-internals/memory-model) describes it.

## Passes After Array Lowering

**`PredicatedSimplification`** simplifies each branch of a select under the select's own condition. Code that runs under a runtime condition often computes something the condition decides, such as the wrap of an index that the condition proves non-negative.

**`SelectMerge`** collapses `select(p, x, y)` to `x` when `y` equals `x` wherever `p` is false (and symmetrically), using the integer interval of a value the condition compares with a constant.

**`ConstantSelectorQueries`** answers equality queries on values that are selected from a finite set of constants by reusing the selection's conditions. **`NeutralNegation`** rewrites `-(a - b)` as `b - a` for unrounded subtractions.

**`AssertSubsumption`** collapses groups of `AssertU128Lt(base + s_k, hi)` with the same runtime `base` and `hi` to the members with the largest and smallest offsets, whose conjunction implies the others.

**`DynamicNDArrayMetaAssertInjection`** adds an `AssertDynamicNDArrayMeta` after each `WitnessDynamicNDArrayMeta`, checking a dynamic-array input's runtime shape against its envelope. It runs when the circuit has a bounded dynamic array input or `enable_memory_consistency` is set in `ZinniaConfig`.

**Unread inputs.** An input that nothing but its own domain check reads takes no part in the proven statement, so `ir_gen::input_domain::drop_checks_of_unread_inputs` removes the check and the final `DeadCodeElimination` removes the read.

**`CheckedAbsSquare`** (`pattern_match_optim.rs`) runs last. It rewrites the square of an absolute value of a checked input, and turns the implicit domain restriction of that `AbsF` into an explicit assertion. It must follow every algebraic simplification, so that no restriction survives for a square that a later rewrite would have removed.

## Running Passes

`apply_pass` in `src/lib.rs` maps each name to its pass. Passes that rebuild the graph through a new `IRBuilder` lose the graph's side tables, so `apply_pass` carries the elided-output list and the provenance table across each pass and drops provenance records whose values no longer exist. `ZINNIA_COMPILE_PHASE_TRACE=1` prints the time and the statement count after every pass. [Adding Optimization Passes](/docs/contributing/adding-optimization-passes) shows how to add one.
