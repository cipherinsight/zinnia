# Intermediate Representation

The IR connects IR generation to the passes and the backends. It is a list of statements in which every statement defines at most one value and reads only values defined before it. There are no jumps: control flow has already become data flow through selects. Its definitions are in `src/ir.rs` (statements and the graph), `src/ir_defs.rs` (the instruction enum `IR`) and `src/ir_array.rs` (array accesses).

## Values

Every value is an element of the prime field of the backends, BN254's scalar field. The IR distinguishes three number kinds by instruction:

- **Integers** (`..I` instructions) are signed 64-bit values. A negative integer `-v` is the field element `p - v`.
- **Floats** (`..F` instructions) are fixed-point numbers with 32 fractional bits: the real number `x` is the integer `round(x * 2^32)`. Multiplication and division rescale.
- **Booleans** are integers equal to 0 or 1.

The value semantics of every instruction are defined by the computation kernel `src/prove/kernel.rs`, which the mock backend evaluates and the other backends constrain.

## Statements and the Graph

An `IRStatement` (`src/ir.rs`) has:

| Field | Meaning |
|---|---|
| `stmt_id` | its position in the statement list |
| `value_id` | the identity of the value it defines, used by facts and the provenance table |
| `ir` | the instruction, a variant of `IR` with its parameters |
| `arguments` | the `stmt_id`s of its operands, all smaller than its own |
| `arg_values` | the same operands as `value_id`s |
| `dbg` | optional source location |

An `IRGraph` holds the statements together with adjacency lists (`in_links`, `out_links`) and degrees, the `value_id → stmt_id` map, the output cells that were constant and therefore left out of the public vector (`elided_publics`), and the provenance table (`src/provenance.rs`), where IR generation records structural facts that later passes and backends read.

Statement order is a topological order of the dependency graph. Passes keep this invariant, and backends rely on it to process statements in one forward walk.

## Instructions

`IR` has about 130 variants. They group as follows (see the section comments in `src/ir_defs.rs`):

| Group | Examples |
|---|---|
| Constants | `ConstantInt`, `ConstantFloat`, `ConstantBool`, `ConstantStr` |
| Integer arithmetic and bit operations | `AddI`, `SubI`, `MulI`, `DivI` (exact division), `FloorDivI`, `ModI`, `PowI`, `AbsI`, `SignI`, `InvI`, `BitAndI`, `ShlI`, ... |
| Float arithmetic | `AddF`, `SubF`, `MulF`, `DivF`, `FloorDivF`, `ModF`, `PowF`, `PowFI`, `AbsF`, `SignF`, and the aggregates `SumF` and `ProductSumF` |
| Comparisons | `EqI`, `NeI`, `LtI`, `LteI`, `GtI`, `GteI` and the float versions; `LtIBounded`, `GtIBounded` and `IndexInBox` (a 0/1 mask for `lo_k <= idx_k < hi_k` on every axis) for operands known to be non-negative and below 2^128 |
| Math functions | `SqrtF`, `ExpF`, `LogF`, `SinF`, `CosF`, `TanF`, `SinHF`, `CosHF`, `TanHF`, `ArcSinF`, `ArcCosF`, `ArcTan2F`, `SqrtProductIF` |
| Logic and selection | `LogicalAnd`, `LogicalOr`, `LogicalNot`; `SelectI`, `SelectF`, `SelectB` (`select(c, a, b)` is `a` where `c` is 1 and `b` where it is 0), `SelectBitI`/`SelectBitF`, `SelectManyI`/`SelectManyF` |
| Casts | `IntCast`, `FloatCast`, `BoolCast` |
| Inputs and outputs | `ReadInteger`, `ReadFloat`, `ReadHash` (a circuit input at an `InputPath`, public or private), `ExposePublicI`, `ExposePublicF` (an output on the public vector) |
| Checks | `Assert`, `AssertBit`, `AssertNonNegI`, `AssertU128Lt` (`0 <= x < hi`), `AssertU128LtBit` (a bit of `x`, with the same check) |
| Facts with no constraint | `ScalarPrecondition`, `StructuralPredicate` (a precondition for the optimizer), `ArrayFact` (a claim about the cells of an array, read and removed by the array lowering layer) |
| Arrays | `ArrayInit`, `ArrayWrite`, `ArrayRead` (array versions); `RomInit`, `RomRead`, `RamInit`, `RamWrite`, `RamRead` (tables and memories, emitted by the lowering layer) |
| Bounded dynamic array metadata | `AllocateDynamicNDArrayMeta`, `WitnessDynamicNDArrayMeta`, `AssertDynamicNDArrayMeta` |
| External calls | `ExportExternalI`, `ExportExternalF`, `InvokeExternal`, `ReadExternalResult` |
| Hashing | `PoseidonHash`, `EqHash` |
| Array operators and their constructions | `ArrayOp` (a placeholder), `Hint`, `IdentityCheck`, `KeyLess`, `PackKey`, `PackedKeyLess`, `PackedKeyIndex`, `RescaleRawF` |
| Strings and printing | `AddStr`, `StrI`, `StrF`, `Print` (no constraints) |

Three groups need more explanation.

**Array versions.** An array version is one statement whose value is a whole vector of cells. `ArrayInit` builds a version from its operands, `ArrayWrite(version, positions..., value, predicate)` defines a new version with one cell replaced where the predicate is nonzero, and `ArrayRead(version, positions...)` reads one cell. An `ArrayAccess` names the cell `offset + Σ i_k · stride_k`, and a position outside its axis has no witness. These operations are pure, so dead-code elimination and duplicate elimination treat them like any other statement. [Arrays and Memory](/docs/compiler-internals/memory-model) describes how they are produced and lowered.

**Array operator placeholders.** For operators such as `np.sort`, a crop by runtime bounds or `np.insert` at a runtime position, IR generation emits one `ArrayOp` statement per output element (a *lane*) instead of the full computation. Dead-code elimination removes the lanes nothing reads, and the array lowering layer replaces the rest with constructions. No backend accepts an `ArrayOp`.

**Hints.** A `Hint` is a value the prover computes outside the circuit, for example the stable argsort of an array. A hint constrains nothing by itself, so every construction that emits one also emits constraints under which the honest value is the only one accepted, and states the argument next to its code (`src/lower/sort/`). `IdentityCheck` asserts an identity such as a multiset equality or a matrix product, which halo2-base checks at a random verifier challenge.

## Fixed Statements

`IR::is_fixed` lists the statements that dead-code elimination keeps even when nothing reads them: the checks, `IdentityCheck`, `Print`, `ExposePublicI`/`ExposePublicF`, the reads of public inputs, the dynamic-array metadata statements, the external-call statements, `ReadHash`, `EqHash` and the precondition statements. Every other statement is live only if a fixed statement depends on it.

## Inspecting the IR

- `ZKCompiledProgram.get_ir_stmts()` returns the compiled IR as a list of dictionaries (`export_ir_json` in `src/lib.rs`), each with the statement id, the instruction (its class name and parameters) and the argument ids.
- `ZINNIA_LAYER_INPUT=<path>` appends the IR that reaches the array lowering layer to a file, one statement per line in the form `%<id> = <signature>(<arguments>)`, for example `%7 = mul_i(%3, %3)`. The signature strings come from `IR::signature`.
