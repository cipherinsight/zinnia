# Compiler Internals Overview

This section is for contributors who need to understand or change the compiler. It describes the code as it is: where each stage lives, what data it passes on, and which invariants the next stage relies on.

## The Problem the Compiler Solves

A zk-SNARK proves that a fixed arithmetic circuit is satisfied. The circuit has a fixed set of gates and wires over a prime field, with no branches, no loops whose trip count depends on the inputs, and no memory that can be addressed at a position chosen at run time. Zinnia programs are Python functions using NumPy, with `if` statements on private values, loops, and arrays indexed at runtime positions. The compiler turns such a function into one static circuit whose constraints hold exactly when the outputs are what Python and NumPy would compute from the inputs.

It does this in three steps:

1. **IR generation by symbolic execution.** The compiler runs the function once over symbolic values. Code whose execution depends on a runtime value is compiled anyway, under a Boolean *execution predicate* that says on which inputs Python would execute it. Loops are unrolled, function calls are inlined, and the values a name may hold after a branch are merged with a select (a multiplexer). The result is a straight-line intermediate representation (IR).
2. **Optimization and array lowering.** IR passes simplify the program and remove what nothing needs. Array operators such as `np.sort`, a read at a runtime index or a write at a runtime position are left as compact placeholders until the array lowering layer chooses, for each one, the cheapest construction on the compile target.
3. **Proving.** A backend walks the final IR and either evaluates it (the mock backend), synthesizes a halo2-base circuit, or emits a Noir program.

## Where the Code Lives

The compiler is a Python package `zinnia/` with a native extension `zinnia._zinnia_core` written in Rust (`src/`, built with maturin).

| Stage | Code |
|---|---|
| Decorators, source lowering, AST transformer | `zinnia/api/`, `zinnia/compile/lowering/`, `zinnia/compile/transformer/` |
| Python-to-Rust entry points | `zinnia/compile/_bridge.py`, `src/lib.rs` |
| AST, as the Rust core reads it | `src/ast/mod.rs` |
| IR generation | `src/ir_gen/`, `src/builder.rs` and `src/builder/`, `src/helpers/`, `src/ops/`, `src/scope.rs`, `src/ir_ctx.rs` |
| Types and values during IR generation | `src/types/` |
| IR | `src/ir.rs`, `src/ir_defs.rs`, `src/ir_array.rs` |
| Optimization passes, constant resolution, facts | `src/optim/` |
| Array lowering layer | `src/lower/` |
| Backends | `src/prove/` (mock, `halo2_base/`, `noir/`) |
