# Control Flow

Zinnia accepts Python's control-flow statements. A circuit has a fixed structure, so every
loop and recursive call is unrolled at compile time and every branch whose condition
depends on an input is compiled in full. This page describes how each construct is
compiled and what the compiler needs to prove for it.

## If / Elif / Else

```python
if x > 0:
    result = x
elif x == 0:
    result = 0
else:
    result = -x
```

### Compiling Branches

When the condition is known at compile time, only the branch that runs is compiled. When it
depends on an input, the compiler evaluates both branches and merges every variable they
assign with a select on the condition:

```python
if cond:
    x = a
else:
    x = b
# compiles to x = select(cond, a, b), that is cond * a + (1 - cond) * b
```

Both branches contribute constraints, so the circuit structure does not reveal which branch
was taken. An `elif` chain is a nested `if` in the `else` branch and compiles to nested
selects. Assertions and writes inside a branch take effect only when the branch's condition
holds (see [Assert Statements](#assert-statements)).

## While Loops

```python
i = 0
total = 0
while i < 10:
    total = total + i
    i = i + 1
```

### Unrolling

A `while` loop is unrolled one iteration at a time. After each iteration the compiler tries
to prove that the condition is false, using constant values, the known ranges of the
values the condition reads, preconditions, and finally an SMT query. When it succeeds, the
loop ends there and the circuit asserts that the condition is indeed false at that point.
Each unrolled iteration runs under the condition that the loop is still running, so
iterations past the actual runtime count have no effect.

```python
@zk_circuit(requires=[lambda n: 0 <= n <= 6])
def triangle(n: Integer) -> Integer:
    i = 0
    total = 0
    while i < n:          # n is private, but the precondition bounds it by 6
        total += i
        i += 1
    return total
```

A counted loop, `while i < b` (or `<=`, `>`, `>=`) where `i` holds a compile-time integer
before the loop and the body changes `i` only through one `i += c` (or `i -= c`), is
compiled like the equivalent `for` loop over `range`.

### Loop Limit

If the condition is not proved false within `loop_limit` unrolled iterations, compilation
fails with an error asking for a bound on the values the condition depends on (a bounded
array annotation or a precondition). The default limit is **1000** and can be changed with
`ZinniaConfig(loop_limit=...)`.

## For Loops

### Range-Based For Loops

```python
total = 0
for i in range(10):
    total = total + i

for i in range(1, 11):
    total = total + i

for i in range(0, 20, 2):
    total = total + i
```

When the arguments of `range` are known at compile time, the loop has a fixed number of
iterations. When they are runtime values (for example `range(n)` with a private `n`), the
loop is unrolled to a proven upper bound, and each unrolled iteration runs only if it
exists at runtime. The circuit also asserts that the iteration after the last unrolled one
does not exist, so an input that would need more iterations has no valid proof. If no
upper bound can be proved, the program is rejected.

### Iterating over Values

```python
values = [10, 20, 30, 40]
total = 0
for v in values:
    total = total + v

for i, v in enumerate(values):
    total = total + i * v

for a, b in zip(xs, ys):
    total = total + a * b
```

A loop over a list, tuple or array runs once per element. A loop over a `DynamicNDArray`
is unrolled to the array's bound, and iterations beyond its runtime length have no effect.

## Break and Continue

```python
# Find the first negative value
result = -1
for i in range(len(data)):
    if data[i] < 0:
        result = i
        break
```

```python
# Sum only positive values
total = 0
for v in values:
    if v <= 0:
        continue
    total = total + v
```

In the circuit, `break` and `continue` do not remove iterations. They change the condition
under which later statements run: after a `break`, the remaining iterations run under a
false condition, and after a `continue`, the rest of the current iteration does.

## Early Return

A function may return from inside a branch or a loop.

```python
@zk_circuit
def find_index(arr: NDArray[Integer, 100], target: Integer) -> Integer:
    for i in range(100):
        if arr[i] == target:
            return i
    return -1
```

Once a `return` is reached on a path, the statements after it run under a false condition
on that path. The returned value is the merge of the values at all `return` statements,
each selected by the condition under which it is reached.

## Recursion

A chip (a function decorated with `@zk_chip`) may call itself. Each call is inlined, so the
recursion must be bounded.

```python
@zk_chip
def fibo(n: Integer) -> Integer:
    if n < 2:
        return n
    return fibo(n - 1) + fibo(n - 2)

@zk_circuit(requires=[lambda n: 0 <= n <= 6])
def fibo_check(n: Integer, out: Public[Integer]):
    assert fibo(n) == out
```

### Bounding the Recursion

A recursive call is inlined as long as the condition under which it is reached may hold.
At each depth the compiler tries to prove that condition false, from constants, the ranges
of the compared values, the preconditions, and finally an SMT query. Once it is proved
false, the call is not inlined and the circuit asserts that it is not reached. In the
example, the precondition `n <= 6` bounds the depth. A bound can also come from arguments
that shrink with every call, or from arguments known at compile time (`fibo(5)`).

### Recursion Limit

The default limit on nested chip calls is **16** (`ZinniaConfig(recursion_limit=...)`). A
recursive call that is not proved unreachable within this many nested calls makes
compilation fail with a `RecursionLimitExceededError` naming the chip. A branching
recursion such as `fibo` inlines up to `2^depth` calls, which is why the default is small.

## Assert Statements

```python
assert x >= 0
assert x + y == expected
assert balance >= withdrawal, "insufficient funds"
```

An assertion compiles to a constraint that holds only if the condition is true. It is
guarded by the condition of the path it is on, so an assertion inside a branch applies only
when that branch is taken.

```python
if mode == 1:
    assert x > 0    # enforced only when mode == 1
else:
    assert x <= 0   # enforced only when mode != 1
```

The assertion message is ignored by the compiler.

## Pass Statements

`pass` is a no-op and produces no constraints.
