# Type System

Zinnia infers the type of every value during compilation. Annotations are required only on
circuit parameters, where they declare the type of each input, and are optional elsewhere.
All values are ultimately represented by field elements of the backend's prime field.

## Scalar Types

### Integer

`Integer`, `Int`, `integer` and `int` name the integer type. An integer input is
constrained to the signed 64-bit range of NumPy's `int64`.

```python
@zk_circuit
def f(x: Integer, y: Int) -> Integer:
    return x + y
```

### Float

`Float` and `float` name the floating-point type. Floats are represented in fixed point
with 32 fractional bits (a value `v` is stored as the integer `round(v * 2^32)`). A float
input is constrained to the range `-2^31 <= v < 2^31`. See
[Real Arithmetic](/docs/data-analytics/real-arithmetic) for the precision this gives.

```python
@zk_circuit
def area(r: Float) -> Float:
    return 3.14159 * r * r
```

### Boolean

`Boolean`, `Bool`, `boolean` and `bool` name the Boolean type. A Boolean is stored as an
integer constrained to 0 or 1, and a Boolean input is checked to be 0 or 1.

```python
@zk_circuit
def g(flag: Bool, x: Integer) -> Bool:
    return flag and x > 0
```

### Complex

`Complex` and `complex` name the complex type. A complex value is stored as two floats (the
real and imaginary parts).

## Composite Types

### List

Lists are ordered sequences. In an annotation, `List[T1, T2, ...]` gives the type of each
element.

```python
xs = [1, 2, 3, 4, 5]
ys = [True, False, True]
```

Lists support the `append`, `extend`, `insert`, `pop`, `copy`, `clear`, `reverse`, `index`,
`count` and `remove` methods.

### Tuple

Tuples are fixed-length sequences whose elements may have different types. In an
annotation, `Tuple[T1, T2, ...]` gives the type of each element.

```python
pair = (1, 3.14)
```

Tuples support the `count` and `index` methods.

## Array Types

### NDArray

An `NDArray` is an N-dimensional array whose shape is known at compile time. It is the
array type most programs use. NumPy arrays created inside a circuit (`np.zeros`,
`np.asarray`, results of array operations) are `NDArray` values.

An input of this type is annotated in one of two equivalent forms: the element type
followed by the dimensions, or the element type indexed by `Array` and a shape string.

```python
NDArray[Integer, 3, 4]       # a 3x4 integer matrix
NDArray[Float, 10]           # a float vector of length 10
Float[Array, "2 3"]          # a 2x3 float matrix
Integer[Array, "N=4"]        # a vector of length 4 whose length is named N
```

The element type is `Integer`, `Float`, `Boolean` or `Complex`. In the shape-string form,
a dimension may be a number, a named number (`N=4`), or a name or expression over names
whose value is fixed by a precondition (for example `@requires(lambda: N == 2)`).

### DynamicNDArray

A `DynamicNDArray` is an array whose shape is a runtime value bounded at compile time. The
circuit is sized for the bound, and the array carries its actual shape as runtime
metadata. See [Arrays](/docs/language/arrays) and
[Bounded-Dynamic Arrays](/docs/data-analytics/bounded-dynamic-arrays).

```python
DynamicNDArray[Float, 1024, 2]   # at most 1024 elements, rank at most 2
Float[DynArray, "N<=1024"]       # a vector of runtime length N, at most 1024
```

Operations whose result shape depends on data, such as boolean-mask indexing or
`filter`, also produce `DynamicNDArray` values.

## Special Types

### PoseidonHashed

`PoseidonHashed[T]` is an input of type `T` that comes with a Poseidon hash of its value.
The circuit computes the hash of the value and asserts that it equals the supplied hash.
See [Privacy Annotations](/docs/language/privacy-annotations#poseidonhashed).

### String

String literals can be used as labels, for example in `print` calls and assertion
messages. Strings cannot be circuit inputs and do not take part in computation.

### None

`None` is the value of a function without a `return` value.

## Merging Values After a Branch

A variable can hold values of different types at different points of the program. When
an `if` statement's condition is a runtime value, the compiler evaluates both branches and,
for every variable assigned in them, selects the value with the condition. If the two
values have different types, the result has the wider type.

```python
if flag:
    x = 42       # Integer
else:
    x = 3.14     # Float
# x is a Float here
```

### Scalars

| Values merged         | Result    |
|-----------------------|-----------|
| Boolean and Boolean   | Boolean   |
| Boolean and Integer   | Integer   |
| Integer and Integer   | Integer   |
| any and Float         | Float     |
| any and Complex       | Complex   |

A variable assigned in only one branch is merged with its value before the `if`.

```python
x = True           # Boolean
if condition:
    x = 42         # Integer in this branch
# x is an Integer here
```

When the condition is known at compile time, only the branch that runs is compiled and no
merge happens.

### Arrays

Arrays of the same shape are merged element by element. One-dimensional arrays of
different lengths are merged into a `DynamicNDArray` whose length is selected at runtime.
For multi-dimensional arrays of different shapes, or an array and a number, no single
value represents both: the program compiles only if the variable is assigned again before
it is used.

```python
if condition:
    v = np.zeros(3)
else:
    v = np.zeros(5)
# v is a DynamicNDArray of length 3 or 5
```
