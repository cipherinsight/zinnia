# Real-Valued Arithmetic

Circuit values are elements of the BN254 scalar field, that is, integers modulo the prime

```
p = 21888242871839275222246405745257275088548364400416034343698204186575808495617
```

To compute with real numbers, Zinnia stores every `Float` as a fixed-point number.

## Fixed-Point Encoding

A real number `x` is stored as the integer

```
x_q = round(x * 2^32)
```

so a `Float` has 32 fractional bits (the Q32 format). A negative `x_q` is stored as the field
element `p + x_q`. Reading a field element back, values above `(p - 1) / 2` are taken as
negative. The resolution is `2^-32`, about `2.3e-10`, and the precision is absolute: a value
near 1000 has the same absolute resolution as a value near 1.

The number of fractional bits is the `precision_bits` proving parameter, which defaults to 32.
The Noir backend's fixed-point library is written for Q32.

Float inputs are rounded to the nearest Q32 value when the witness is built, and float
outputs are converted back by dividing by `2^32`.

## Supported Range

The arithmetic that rescales or divides (multiplication, division, the non-linear functions)
requires its results to lie in the signed 64-bit window of the encoding, `-2^63 <= x_q < 2^63`,
which means `|x| < 2^31`, about `2.1e9`. When a result falls outside this window, the circuit
has no satisfying assignment, so no proof can be produced. The mock backend reports such an
execution as unsatisfied.

## Arithmetic Operations

### Addition and Subtraction

Addition and subtraction are field additions of the encoded values and are exact:
`x_q + y_q = (x + y) * 2^32`.

### Multiplication

The product of two encoded values carries the scale twice, `x_q * y_q = x * y * 2^64`, so the
circuit divides it by `2^32` and rounds down:

```
(x * y)_q = floor(x_q * y_q / 2^32)
```

The circuit checks the quotient and remainder of this division with range checks. Products
with an integer, or with a constant whose encoding has trailing zero bits, need less or no
rescaling.

### Division

`x / y` computes the quotient `q` with `x_q * 2^32 = y_q * q + r` and `0 <= r < |y_q|`, so the
result is rounded down. The quotient must lie in the signed 64-bit window. Division by zero
gives 0, because fixed point cannot represent NumPy's `inf` or `nan`.

`x // y` and `x % y` on floats follow Python's floor-division convention: the remainder has
the sign of the divisor.

### Conversions

`int(x)` truncates toward zero, as in Python. `float(n)` of an integer is
exact for integers that fit the window.

### Accumulated Error

Every multiplication and division rounds down by less than one unit in the last place,
`2^-32`. Long chains of multiplications accumulate this error, and inputs are rounded to Q32
before the computation starts, so results differ from IEEE double precision in the low bits.
Compare results with a tolerance (for example `np.isclose` or `np.allclose`, which are
supported inside circuits) rather than exact equality.

## Integer Arithmetic

`Integer` values follow NumPy's `int64` semantics. Addition, subtraction and multiplication
are field operations and are exact, and outputs are reported as `int64`, so a result that
leaves the 64-bit range wraps as in NumPy. Integer division (`//`, `%`), shifts and bitwise
operators require their operands to lie in the `int64` range, and otherwise have no proof.
Integer floor division uses Python's rounding (toward negative infinity).

## Choosing Between Float and Integer

| Use case | Type | Reason |
|----------|------|--------|
| Counting, indexing, exact equality | `Integer` | No rounding |
| Amounts with a known number of decimals | `Integer` (scaled) | Exact at the chosen precision |
| Statistics, scientific computation | `Float` | Real-valued results, non-linear functions |
| Flags and masks | `Boolean` | Values restricted to 0 and 1 |

## Practical Considerations

- Keep magnitudes well below `2^31`. Normalize or rescale data whose values or intermediate
  products (for example sums of squares) could reach the limit.
- Prefer integers when the data is integral. Integer arithmetic needs no rescaling, and its
  comparisons are exact.
- Expect small differences from NumPy's double-precision results and compare with a
  tolerance.
