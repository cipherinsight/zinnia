# Non-Linear Functions

Arithmetic circuits natively support only field addition and multiplication. Zinnia computes
`exp`, `log`, `sqrt`, the trigonometric and hyperbolic functions and `arctan2` on
[Q32 fixed-point values](/docs/data-analytics/real-arithmetic) with integer algorithms: a
range reduction followed by a polynomial or a series, in which every product is rounded down.
The mock backend evaluates the same algorithms that the halo2-base and Noir backends
constrain, so the mock result is the value a proof attests to. `arccos` is the exception (see
the table).

## Calling the Functions

The functions are available under `np` and `math` and apply element-wise to arrays:

```python
import math
from zinnia import *

@zk_circuit
def features(x: NDArray[Float, 8]) -> NDArray[Float, 8]:
    return np.exp(-x) + np.sin(x)

@zk_circuit
def norm2(a: Float, b: Float) -> Float:
    return math.sqrt(a * a + b * b)
```

## Supported Functions

| Function | Spelling | Algorithm | Domain |
|----------|----------|-----------|--------|
| Exponential | `np.exp`, `math.exp` | `2^(x / ln 2)`: integer part as a shift, fractional part by a degree-12 polynomial for `2^f` on `[0, 1)` | result below `2^31` (`x` up to about 21.48) |
| Natural logarithm | `np.log`, `math.log` | `x = m * 2^k` with `m` in `[1, 2)`, then `k ln 2 + 2 atanh((m - 1) / (m + 1))` by a series | `x > 0` |
| Square root | `np.sqrt`, `math.sqrt` | exact integer square root, rounded down | `x >= 0` |
| Sine, cosine | `np.sin`, `np.cos`, `math.sin`, `math.cos` | reduction modulo `2π` and folding onto `[0, π/2]`, then a degree-9 odd polynomial; `cos(x) = sin(x + π/2)` | all `x` in the Q32 range |
| Tangent | `np.tan`, `math.tan` | `sin(x) / cos(x)` | mock and Noir backends only |
| Hyperbolic functions | `np.sinh`, `np.cosh`, `np.tanh` (and `math.*`) | from `exp(x)` and `exp(-x)`; `tanh = sinh / cosh` | both exponentials in range |
| Arcsine | `np.arcsin`, `math.asin` | `2 atan(x / (1 + sqrt(1 - x^2)))` with a polynomial for `atan` on `[-1, 1]` | `-1 <= x <= 1` |
| Arccosine | `np.arccos`, `math.acos` | Noir: `π/2 - arcsin(x)`; the mock backend uses the C library's `acos`, so its result can differ from Noir's in the last bits | `-1 <= x <= 1`; mock and Noir backends only |
| Two-argument arctangent | `np.arctan2`, `math.atan2` | ratio of the smaller to the larger magnitude, polynomial for `atan` on `[0, 1]`, then octant and sign corrections | all `(y, x)`; `arctan2(0, 0) = 0` |
| Power | `x ** y`, `np.power` | integer exponent: square-and-multiply; float exponent: `exp(y * log x)` | see below |

`np.abs`, `np.fabs`, `np.sign`, `np.floor`, `np.ceil`, `np.trunc`, `np.round`,
`np.square`, `np.reciprocal`, `np.minimum`, `np.maximum` and `np.clip` are also supported.
They need comparisons or rescaling but no approximation.

The halo2-base backend reports an error for `tan` and `arccos` when proving. Express them
through the supported functions if you need a halo2-base proof, for example
`np.sin(x) / np.cos(x)`.

## Domains

For `sqrt`, `log`, `arcsin` and `arccos`, the compiler checks the domain condition in the
table. When it can prove the condition from the program (for example from a constant, an
earlier comparison or a precondition), it adds nothing. When it can prove that the condition
fails, compilation stops with an error. Otherwise it adds a check to the circuit, so an input
that violates the condition has no proof.

The other limits come from the Q32 range. `exp` has no proof when its result would reach
`2^31`. For powers, `0 ** y` with negative `y` and a negative base with a non-integer
exponent have no proof, since NumPy returns `inf` or `nan` there. `0 ** 0` is 1, as in NumPy.

## Accuracy

The shared fixed-point kernel (`src/prove/kernel.rs`) documents these maximum errors against
the C math library at 32 fractional bits:

| Function | Measured maximum error |
|----------|------------------------|
| `exp` on `[-40, 21.4]` | relative `9.4e-10` for results of at least 1, absolute `9.4e-10` below 1 |
| `log` on `[2^-32, 2^31)` | absolute `1.3e-9` |
| `sin` | `9.0e-9` on `[-20, 20]`, `4e-8` on `[-1000, 1000]` |
| `arcsin` on `[-1, 1]` | `5.9e-9` |
| `arctan2` | `3.2e-9` |

The error of `x ** y` with a float exponent is about `1e-9 + |y| * 1.3e-9` relative, the error
of `exp` plus `y` times the error of `log`. `sqrt` is exact up to rounding down to Q32.

## Practical Considerations

- Each call is evaluated independently. Applying `np.sin` to a 100-element array produces 100
  evaluations.
- Keep arguments of `exp`, `sinh` and `cosh` small enough that the result stays below
  `2^31`. Normalizing data before applying `exp` (for example subtracting the maximum in a
  softmax) avoids this limit.
- A low-degree polynomial written directly in the program can be cheaper than composing
  `exp` and a division when an approximation of the function is acceptable for the
  application.
