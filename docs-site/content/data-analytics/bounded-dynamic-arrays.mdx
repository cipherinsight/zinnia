# Bounded-Dynamic Arrays

A circuit has a fixed size, so every array in it needs a size known at compile time. Some
arrays nevertheless have a shape that depends on the data, such as the elements of a private
array that exceed a threshold, or an input whose length differs between proofs. Zinnia
represents such an array as a *bounded-dynamic array*. It consists of a buffer whose size is a
compile-time upper bound, called the *envelope*, and a *runtime shape* that says which part of
the buffer holds the array. The circuit size depends only on the envelope.

## The Envelope

An envelope fixes three things at compile time:

| Parameter | Meaning |
|-----------|---------|
| element type | `Integer`, `Float` or `Complex` (Booleans are stored as integers) |
| maximum length | the number of buffer slots, an upper bound on the number of elements |
| maximum rank | the largest number of axes the array may have |

Envelopes derived from per-axis bounds also record the bound of each axis.

## Runtime Shape

When a proof is generated, the array has a runtime shape: its rank and the extent of each
axis. The circuit checks that every extent lies between 0 and its bound and that the number
of elements fits the buffer. Slots beyond the runtime shape hold padding (zero), and
operations use only the active elements, so the padding never reaches a result.

## Declaring Inputs

There are three ways to annotate a circuit input with a runtime shape.

```python
from zinnia import *

# One axis of at most 1024 elements
@zk_circuit
def total(x: Float[DynArray, "N<=1024"]) -> Float:
    return np.sum(x)

# Per-axis bounds: at most 100 rows of exactly 3 columns
@zk_circuit
def column_sums(m: Float[Array, "R<=100 3"]) -> Float:
    return np.sum(m)

# Element type, maximum length and maximum rank
@zk_circuit
def count_rows(a: DynamicNDArray[Integer, 6, 2]) -> Integer:
    return a.shape[0]
```

A bound may also come from a precondition instead of the annotation:

```python
@zk_circuit
@requires(lambda: 1 <= N <= 512)
def first(x: Float[DynArray, "N"]) -> Float:
    return x[0]
```

A shape symbol without any bound is rejected at compile time.

When proving, pass an ordinary array of the actual shape (for example `np.asarray(...)` with
3 elements for `N<=1024`). The witness builder pads it to the envelope and rejects an array
that exceeds a bound.

**Privacy.** The runtime shape of a bounded-dynamic input is a public input of the proof. The
verifier learns the length (and the extent of each axis), while the elements stay private
unless the input is annotated `Public[...]`. The envelope is part of the circuit and is
therefore public as well.

## Operations That Produce Runtime Shapes

Inside a circuit, the compiler produces a bounded-dynamic array when a result's shape
depends on values that are not known at compile time:

- **Boolean-mask selection** with a mask computed from runtime values, as in
  `data[data > threshold]`. The envelope is the size of `data`. Selecting rows of a 2-D array
  with a 1-D mask keeps the trailing axes.
- **Data-dependent selections** such as `np.nonzero`, `np.flatnonzero`, `np.compress` and
  `np.unique`.
- **Constructors with a runtime extent**, such as `np.zeros((3, n))` where `n` is a circuit
  value with a bound (for example from `@requires(lambda n: 0 <= n <= 10)`). Without a bound
  the program is rejected.
- **Branches that bind 1-D arrays of different lengths** to the same name under a runtime
  condition. Multi-dimensional arrays of different shapes, or an array and a number, cannot be
  merged: the program is rejected if it uses such a name before rebinding it.
- **`np.promote_to_dynamic(a)`**, a Zinnia extension that turns a static array into a
  bounded-dynamic one.

Many operations accept bounded-dynamic arrays, among them element-wise arithmetic,
reductions such as `np.sum` and `np.mean`, indexing, `reshape`, `transpose`, `concatenate`,
`stack` and `split`. An array result is again bounded-dynamic, with an envelope the compiler
derives from the envelopes of the operands.

```python
@zk_circuit
def mean_of_positives(data: NDArray[Float, 100]) -> Float:
    positives = data[data > 0.0]       # envelope: 100 elements, rank 1
    return np.sum(positives) / positives.shape[0]
```

Annotations on local variables are ignored (types are inferred), so writing
`x: DynamicNDArray[Float, 100, 1] = ...` inside a circuit does not make `x` dynamic.

## Limitations

- The `np.linalg` verification helpers (`verify_inverse`, `verify_solve`, `verify_cholesky`) do
  not accept bounded-dynamic arrays.
- Some operations that read the buffer as a flat sequence in C order (for example a reshape
  or a flat `argmax`) are rejected on arrays whose inner axes have runtime extents inside a
  padded buffer, such as inputs with per-axis bounds. The error message names the operation.

## Performance Considerations

- Prefer static shapes when they are known. Static arrays avoid the runtime-shape checks and
  give smaller circuits.
- Choose the tightest bound you can justify. The cost of an operation on a bounded-dynamic
  array grows with its envelope, not with its runtime length.
- A runtime-shaped input reveals its shape. If the shape itself must stay private, pad the
  data to a fixed size yourself and pass a private mask or count instead.
