# Array Operations

Zinnia accepts NumPy code: arrays are written with `np` functions, array methods and Python
operators, and follow NumPy's semantics (shapes, broadcasting, dtype rules and integer
`int64` arithmetic). This page lists what is supported and explains which operations cost
constraints.

## What Costs Constraints

The compiler unrolls the program. An operation whose result is determined by compile-time
information costs nothing in the circuit:

- Indexing and slicing a static array with constant indices selects cells at compile time.
- `reshape`, `transpose`, `.T`, `swapaxes`, `moveaxis`, `squeeze`, `expand_dims`,
  `broadcast_to`, `flip`, concatenation and stacking of static arrays rearrange cells at
  compile time.
- Computations on constants are folded.

Arithmetic on circuit values costs constraints per element. Operations whose result depends
on circuit values in a non-arithmetic way, such as indexing with a runtime index, sorting,
selecting by a runtime mask, or order statistics, are *array operators*. The compiler lowers
each of them after optimization by choosing, for the target backend, the cheapest of several
circuit constructions (for example a one-hot selection, a lookup table, a permutation
argument or a routing network) that produces the values the program uses. The choice depends on
the sizes involved and on what the compiler can prove about the operands, for example that
an index is in range or that an array is already sorted.

## Indexing and Slicing

```python
from zinnia import *

@zk_circuit
def example(A: NDArray[Float, 4, 5], i: Integer) -> Float:
    row = A[2]               # shape (5,)
    block = A[1:3, ::2]      # shape (2, 3)
    last = A[-1, -1]         # negative indices count from the end
    picked = A[i, 0]         # runtime index
    return row[0] + block[1, 2] + last + picked
```

- Integer indices, slices with steps, negative indices and `...` are supported.
- An index may be a circuit value (a runtime index).
- Boolean masks select elements, as in `data[data > 0.0]`. With a mask that depends on
  circuit values, the result is a [bounded-dynamic array](/docs/data-analytics/bounded-dynamic-arrays).
- Integer arrays index arrays, as in NumPy's advanced indexing.
- Assignment works through indices, slices and masks: `a[1:3] = 0`, `a[a > 0] = 0`,
  `a[i] = x`.

## Broadcasting

Element-wise operations between arrays of different shapes follow NumPy's broadcasting rules.
Shapes are aligned from the right, and an axis of size 1 is stretched to the other operand's
size. Incompatible static shapes are a compile-time error.

```python
@zk_circuit
def center(A: NDArray[Float, 3, 4]) -> NDArray[Float, 3, 4]:
    return A - np.mean(A, axis=0)    # (3, 4) - (4,)
```

## Element-Wise Operations

The Python operators `+`, `-`, `*`, `/`, `//`, `%`, `**`, unary `-`, comparisons, `&`, `|`,
`^`, `~`, `<<` and `>>` apply element-wise. Comparisons produce Boolean arrays.

Element-wise NumPy functions:

- arithmetic: `np.add`, `np.subtract`, `np.multiply`, `np.divide`, `np.floor_divide`,
  `np.mod`, `np.fmod`, `np.power`, `np.negative`, `np.positive`, `np.square`,
  `np.reciprocal`, `np.abs`, `np.absolute`, `np.fabs`, `np.sign`
- rounding: `np.floor`, `np.ceil`, `np.trunc`, `np.round`, `np.around`
- comparisons: `np.equal`, `np.not_equal`, `np.less`, `np.less_equal`, `np.greater`,
  `np.greater_equal`, `np.minimum`, `np.maximum`, `np.fmin`, `np.fmax`, `np.clip`
- logic: `np.logical_and`, `np.logical_or`, `np.logical_xor`, `np.logical_not`
- non-linear functions: `np.exp`, `np.log`, `np.sqrt`, `np.sin`, `np.cos`, `np.tan`,
  `np.sinh`, `np.cosh`, `np.tanh`, `np.arcsin`, `np.arccos`, `np.arctan2`, `np.deg2rad`,
  `np.rad2deg` (see [Non-Linear Functions](/docs/data-analytics/nonlinear-functions))
- complex numbers: `np.real`, `np.imag`, `np.conj`
- `np.where(cond, x, y)` and `np.select`

Ufuncs accept NumPy's `out` argument. The ufunc methods `np.<ufunc>.reduce` (for `add`,
`multiply`, `minimum`, `maximum`, `logical_and`, `logical_or`), `np.<ufunc>.outer` (for
`add`, `subtract`, `multiply`, `divide`), `np.add.reduceat`, `np.minimum.accumulate` and
`np.maximum.accumulate` are supported.

## Reductions and Statistics

```python
@zk_circuit
def stats(A: NDArray[Float, 4, 5]):
    col_sums = np.sum(A, axis=0)     # shape (5,)
    row_means = A.mean(axis=1)       # shape (4,)
    return np.max(col_sums) + np.std(row_means)
```

- `np.sum`, `np.prod`, `np.min` / `np.amin`, `np.max` / `np.amax`, `np.any`, `np.all`, with
  `axis` and `keepdims`
- `np.mean`, `np.var`, `np.std` (with `ddof`), `np.median`, `np.percentile`
- `np.argmax`, `np.argmin`, `np.cumsum`, `np.cumprod`, `np.diff`
- `np.cov`, `np.corrcoef`, `np.correlate`, `np.convolve`, `np.histogram`, `np.bincount`
- `np.allclose`, `np.isclose`, `np.array_equal`

The corresponding array methods (`A.sum()`, `A.max()`, `A.argmax()`, `A.cumsum()`, ...) are
supported, as are the builtins `sum`, `min`, `max`, `any`, `all`, `abs` and `len`.

## Sorting and Searching

`np.nonzero`, `np.flatnonzero`, `np.argwhere`, `np.take`, `np.take_along_axis`,

## Creating and Reshaping Arrays

- creation: `np.array`, `np.asarray`, `np.zeros`, `np.ones`, `np.empty`, `np.full`,
  `np.zeros_like`, `np.ones_like`, `np.empty_like`, `np.full_like`, `np.identity`, `np.eye`,
  `np.arange`, `np.linspace`, `np.indices`, `np.diag`, `np.triu`, `np.tril`, `np.copy`
- shape: `np.reshape` / `.reshape`, `.ravel`, `.flatten`, `np.transpose` / `.T`,
  `np.swapaxes`, `np.moveaxis`, `np.squeeze`, `np.expand_dims`, `np.broadcast_to`,
  `np.atleast_1d`, `np.atleast_2d`, `np.atleast_3d`
- joining and splitting: `np.concatenate`, `np.stack`, `np.vstack`, `np.hstack`,
  `np.dstack`, `np.column_stack`, `np.block`, `np.split`, `np.array_split`,
  `np.hsplit`, `np.vsplit`, `np.dsplit`
- rearranging: `np.tile`, `np.repeat`, `np.flip`, `np.flipud`, `np.fliplr`, `np.rot90`,
  `np.roll`, `np.pad`, `np.delete`, `np.insert`
- writing: `np.copyto`, `np.putmask`
- conversion: `.astype`, `.tolist`, and the dtype constructors such as `np.float64` and
  `np.int64`

## Linear Algebra

```python
@zk_circuit
def project(A: NDArray[Float, 3, 4], x: NDArray[Float, 4]) -> NDArray[Float, 3]:
    return A @ x
```

- `@` / `np.matmul`, `np.dot`, `np.inner`, `np.outer`, `np.tensordot`, `np.einsum`
- `np.linalg.norm`
- `np.linalg.verify_inverse(A, Y)`, `np.linalg.verify_solve` and
  `np.linalg.verify_cholesky`, Zinnia extensions that check a result supplied as an input
  (for example an inverse `Y` of `A`) instead of computing it in the circuit

`np.linalg.inv`, `np.linalg.solve` and `np.linalg.cholesky` are not available. Compute the
result outside the circuit, pass it as an input, and check it with the matching `verify_*`
function.

## Practical Guidance

- Prefer static shapes and constant indices where the program allows it. They cost nothing.
- Reduce early. A reduction from shape (1000, 50) to (50,) shrinks all later work.
- Give the compiler facts it can use. A precondition such as an index range or sortedness
  (see `@requires`) can let the compiler choose a cheaper construction for an array
  operator.
