# External Functions

A `ZKExternalFunc` represents a helper function that runs in Python, outside the
zero-knowledge circuit. The circuit receives its result as a witness value that it can then
check with constraints.

## Imports

```python
from zinnia import ZKExternalFunc, zk_external
```

## What External Functions Are

Some values are cheap to check inside a circuit but expensive to compute there, such as a
square root, a quotient, or the result of a search. An external function lets the prover
compute such a value in ordinary Python and hand it to the circuit, which then checks it.
In zk-SNARK terminology the returned value is an *advice* (or *hint*) value: part of the
private witness, chosen by the prover and not constrained by the call itself.

External functions are:

- **Callable outside circuits.** Unlike chips, you can call a `ZKExternalFunc` directly in
  Python and it runs the underlying function. This makes them useful for testing and data
  preparation.
- **Evaluated before the constraints are checked.** When a circuit is executed or proved,
  a preprocessing pass evaluates the circuit, calls each external function with the values
  of its arguments, and adds the returned values to the witness.
- **Unconstrained.** The call adds no constraints that relate the result to the arguments.
  A dishonest prover can substitute any value, so the circuit must assert whatever property
  the result is supposed to have.
- **Typed by their return annotation.** The source is parsed when the `ZKExternalFunc` is
  created, and a return annotation (without `Public` or `Private`) is required. Parameter
  annotations are optional.

## Creating External Functions

There are three ways to create a `ZKExternalFunc`.

### Pattern 1: The `@zk_external` Decorator

The most concise approach. The decorator wraps the function and returns a `ZKExternalFunc`
instance that is also callable:

```python
from zinnia import zk_external, Integer

@zk_external
def load_threshold() -> Integer:
    # In a real application, this might read from a file or database
    return 42

# Callable outside a circuit
value = load_threshold()
print(value)  # 42
```

### Pattern 2: `ZKExternalFunc.from_method`

Pass a plain Python function to the factory method:

```python
from zinnia import ZKExternalFunc, Integer

def load_threshold() -> Integer:
    return 42

external = ZKExternalFunc.from_method(load_threshold)

# Still callable
value = external()
print(value)  # 42
```

If you pass a `ZKExternalFunc` instance to `from_method`, it is returned as-is. Passing a
`ZKChip` raises a `ZinniaException`.

### Pattern 3: Constructor with Source and Callable

For advanced use cases, provide the name, source code, and the callable separately:

```python
from zinnia import ZKExternalFunc

source = """
def load_threshold() -> Integer:
    return 42
"""

def load_threshold_impl():
    return 42

external = ZKExternalFunc(
    name="load_threshold",
    source=source,
    the_callable=load_threshold_impl,
)
```

This is useful when the source string (used for AST parsing and return type inference) and
the actual callable come from different origins.

## Using External Functions in Circuits

External functions are passed to a circuit via the `externals` parameter and called by
name inside the circuit body.

### With `ZKCircuit.from_method`

```python
from zinnia import ZKCircuit, zk_external, Integer, Private

@zk_external
def get_max_value() -> Integer:
    return 100

def my_circuit(score: Private[Integer]):
    limit = get_max_value()
    assert score <= limit

circuit = ZKCircuit.from_method(my_circuit, externals=[get_max_value])
result = circuit.mock(85)
print(result.is_satisfied())  # True
```

### With the `@zk_circuit` Decorator

When using `@zk_circuit`, external functions are discovered automatically: every
`ZKExternalFunc` defined at module level in the circuit's module, and every one visible in
the local scope where the circuit is called:

```python
from zinnia import zk_circuit, zk_external, Integer, Private

@zk_external
def get_max_value() -> Integer:
    return 100

@zk_circuit
def my_circuit(score: Private[Integer]):
    limit = get_max_value()
    assert score <= limit

result = my_circuit(85)
print(result.is_satisfied())  # True
```

### Passing Plain Functions as Externals

Plain Python functions in the `externals` list are automatically wrapped with
`ZKExternalFunc.from_method`:

```python
def get_max_value() -> Integer:
    return 100

circuit = ZKCircuit.from_method(my_circuit, externals=[get_max_value])
```

## How External Calls Are Handled

The compiler records each external call site in the circuit IR, together with the values
passed to it and the declared return type. When the circuit is executed on the mock backend
or proved, the preprocessing stage evaluates the IR, invokes the Python function for each
call, and places the returned value in the witness. The constraints are then evaluated with
that witness.

Because the external call itself adds no constraints, check its result in the circuit:

```python
from zinnia import zk_circuit, zk_external, Integer, Private

@zk_external
def isqrt_hint(x) -> Integer:
    return int(x ** 0.5)

@zk_circuit
def has_isqrt(x: Private[Integer], r_expected: Integer):
    r = isqrt_hint(x)
    assert r * r <= x
    assert (r + 1) * (r + 1) > x
    assert r == r_expected
```

## Callable Outside Circuits

Unlike `ZKChip`, a `ZKExternalFunc` can be called at any time. Calling it runs the
underlying Python function:

```python
@zk_external
def preprocess(data: Integer) -> Integer:
    return data * 2 + 1

# Works fine outside any circuit
result = preprocess(10)
print(result)  # 21
```

This makes external functions convenient for unit testing the preprocessing logic
independently of the circuit.

## Serialization Considerations

When serializing a compiled program with `ZKCompiledProgram.serialize()`, external function
callables are not included in the serialized data (functions cannot be serialized to JSON).
Only the external function names are recorded.

When deserializing, you must re-provide the external function instances:

```python
from zinnia import ZKCompiledProgram, ZKExternalFunc

@zk_external
def my_helper() -> Integer:
    return 10

# Serialize
data = compiled_program.serialize()

# Deserialize -- must re-provide externals
restored = ZKCompiledProgram.deserialize(data, external_funcs=[my_helper])
```

If you omit an expected external function, or provide one that was not part of the original
compilation, a `ZinniaException` is raised.

## Complete Example

```python
from zinnia import ZKCircuit, zk_external, Integer, Public, Private

@zk_external
def divide_hint(a, b) -> Integer:
    return a // b

def division_circuit(a: Private[Integer], b: Public[Integer], q_expected: Public[Integer]):
    q = divide_hint(a, b)
    r = a - q * b
    # The hint is unconstrained: check that q is the floor quotient.
    assert 0 <= r
    assert r < b
    assert q == q_expected

circuit = ZKCircuit.from_method(division_circuit, externals=[divide_hint])
print(circuit.mock(17, 5, 3).is_satisfied())  # True
print(circuit.mock(17, 5, 4).is_satisfied())  # False
```
