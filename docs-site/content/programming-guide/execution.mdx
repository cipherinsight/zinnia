# Execution and Proving

A compiled Zinnia circuit can be run in two ways. Mock execution evaluates the circuit's
constraints with concrete inputs and reports whether they hold, without any cryptography.
Proving runs a zk-SNARK backend that produces a proof which a verifier can check.

## Mock Execution

Mock execution is the primary tool for testing and debugging circuits. It is available in
every build, including the default build without proving backends.

### Running a Mock Execution

Call `mock()` on a `ZKCircuit` instance with the input values, in parameter order:

```python
from zinnia import ZKCircuit, Integer, Private, Public

def check_sum(a: Private[Integer], b: Public[Integer]):
    assert a + b == 10

circuit = ZKCircuit.from_method(check_sum)
result = circuit.mock(3, 7)
print(result.is_satisfied())  # True
```

Calling the circuit object is equivalent:

```python
result = circuit(3, 7)
```

Calling a function decorated with `@zk_circuit` also runs a mock execution and returns the
same kind of result.

### Compilation

If the circuit has not been compiled yet, `mock()` calls `compile()` first. Later calls
reuse the compiled program. Call `compile()` explicitly to separate compilation from
execution, for example to measure compilation time:

```python
circuit = ZKCircuit.from_method(check_sum)
compiled = circuit.compile()  # compilation happens here
result = circuit.mock(3, 7)   # only execution happens here
```

### Steps of a Mock Execution

1. **Compilation** (if needed). The source is parsed, lowered to IR and optimized.
2. **Input conversion.** The arguments are checked against the parameter annotations and
   converted to the circuit's witness format.
3. **Preprocessing.** The IR is evaluated once to resolve calls to external functions,
   whose results are added to the witness.
4. **Constraint evaluation.** The mock backend evaluates every constraint with the witness.
5. **Result.** A `ZKExecResult` reports whether all constraints were satisfied.

`circuit.mock(*args)` is shorthand for `circuit.prove(*args, backend="mock")`, wrapped in a
`ZKExecResult`.

## ZKExecResult

| Member | Type | Description |
|--------|------|-------------|
| `is_satisfied()` | `bool` | `True` if all circuit constraints hold. |
| `__bool__()` | `bool` | Allows using the result directly in a Boolean context. |
| `proof` | `ZKProofResult` | The mock backend's artifact. |

```python
result = circuit.mock(3, 7)

if result:
    print("All constraints passed")
if not circuit.mock(1, 2):
    print("At least one constraint failed")
```

## Proving and Verifying

`prove()` compiles the circuit if needed, resolves external calls, and runs the selected
backend. It returns a `ZKProofResult`. `verify()` checks such a result, using the backend
recorded in it.

```python
circuit = ZKCircuit.from_method(check_sum)
proof = circuit.prove(3, 7, backend="halo2-base")
assert circuit.verify(proof)
```

The `backend` argument accepts:

| Backend | Description | Build requirement |
|---------|-------------|-------------------|
| `"mock"` (default) | Evaluates the constraints without cryptography. | Always available. |
| `"halo2-base"` | Builds a Halo2 circuit with the halo2-base (Halo2-lib) library and proves it in-process. | Cargo feature `halo2-base-backend`. |
| `"noir"` | Emits a Noir program and proves it with the `nargo` and `bb` (Barretenberg UltraHonk) tools. | Cargo feature `noir-backend`, plus `nargo` and `bb` installed. |

The legacy names `"halo2"` and `"halo2-ipa"` are rejected with an error that names
`"halo2-base"`. An unknown name, or a backend not compiled into the extension, raises an
error listing the available backends.

The lowering of array operations depends on the target, which is set at compile time by
`ZinniaConfig(backend=...)` (see [Configuration](/docs/programming-guide/configuration)).
Compile with `ZinniaConfig(backend="noir")` before proving with `backend="noir"`. The
default configuration targets halo2-base.

The Noir backend looks for its tools in the `ZINNIA_NARGO_BIN` and `ZINNIA_BB_BIN`
environment variables, then at `~/.nargo/bin/nargo` and `~/.bb/bb`, then on `PATH`.

### Proving Parameters

`prove()` accepts an optional `params` dictionary. When it is given, it must contain all
three keys:

| Key | Meaning |
|-----|---------|
| `k` | Base-2 logarithm of the number of rows of the halo2-base circuit. Ignored by Noir, which sizes its circuit itself. |
| `lookup_bits` | Width in bits of the lookup table used for range checks (halo2-base). |
| `precision_bits` | Number of fractional bits of the fixed-point encoding of `Float` values (32). |

Without `params`, the backend chooses them: halo2-base estimates `k` and `lookup_bits` from
the circuit's cell counts, and Noir uses `{"k": 10, "lookup_bits": 8, "precision_bits": 32}`.

```python
proof = circuit.prove(3, 7, backend="halo2-base",
                      params={"k": 12, "lookup_bits": 8, "precision_bits": 32})
```

### ZKProofResult

| Attribute | Description |
|-----------|-------------|
| `backend` | Name of the backend that produced the artifact. |
| `proof_bytes_hex` | The proof, hex-encoded. For the mock backend, `"mock_satisfied"` or an unsatisfied marker. |
| `vk_bytes_hex` | The verifying key, hex-encoded. |
| `public_values` | The public values of the proof. |
| `k` | The circuit size parameter used. |
| `prove_seconds` | Time spent in the backend's proof generation. |

`to_json()` and `ZKProofResult.from_json()` serialize the artifact, so it can be verified
in another process.

### Reusing halo2-base Keys

`prove()` generates parameters and keys on every call. For repeated proofs of the same
compiled program with the halo2-base backend, generate the keys once:

```python
from zinnia import ZKCompiledProgram

program = circuit.compile()
keys = program.setup()                 # optional params dict as for prove()
proof = program.prove_with_keys(keys, 3, 7)
assert ZKCompiledProgram.verify_with_keys(keys, proof)

keys.save("keys_dir")                  # write parameters and both keys
prover_keys = ZKCompiledProgram.load_keys("keys_dir", role="prover")
verifier_keys = ZKCompiledProgram.load_keys("keys_dir", role="verifier")
```

`prove_with_keys` returns a dictionary with the hex-encoded `"proof"`, its
`"public_values"`, `k`, and the time of each proving phase. `verify_with_keys_report`
returns the verdict together with an error message and the verification time.

### Public Values

Inputs annotated `Public` and the circuit's outputs (its return value, or the array
arguments it writes when it returns `None`) are public values of the proof. Constant
outputs are not included. `ZKCompiledProgram.describe_publics()` lists what each public
value is, by index, and `get_output_layout()` gives the position of every output value.

## Testing Strategy

Mock execution makes circuits easy to test with ordinary Python test frameworks.

### Known Inputs and Boundaries

```python
from zinnia import ZKCircuit, Integer, Private, Public

def age_check(age: Private[Integer], min_age: Public[Integer]):
    assert age >= min_age

circuit = ZKCircuit.from_method(age_check)

assert circuit.mock(25, 18).is_satisfied()
assert not circuit.mock(15, 18).is_satisfied()

# At the boundary and one below
assert circuit.mock(18, 18).is_satisfied()
assert not circuit.mock(17, 18).is_satisfied()
```

### Chips

Test a circuit with inputs that exercise each path of the chips it uses:

```python
from zinnia import ZKCircuit, zk_chip, Integer, Private, Public

@zk_chip
def clamp(value: Integer, lo: Integer, hi: Integer) -> Integer:
    if value < lo:
        return lo
    if value > hi:
        return hi
    return value

def clamped_check(v: Private[Integer], expected: Public[Integer]):
    assert clamp(v, 0, 100) == expected

circuit = ZKCircuit.from_method(clamped_check, chips=[clamp])

assert circuit.mock(50, 50).is_satisfied()
assert circuit.mock(-10, 0).is_satisfied()
assert circuit.mock(200, 100).is_satisfied()
```

### External Functions

External functions are callable outside circuits, so they can be unit tested directly:

```python
from zinnia import zk_external, Integer

@zk_external
def compute_threshold() -> Integer:
    return 42

assert compute_threshold() == 42
```

### pytest

```python
import pytest
from zinnia import ZKCircuit, Integer, Private, Public

def sum_check(a: Private[Integer], b: Private[Integer], total: Public[Integer]):
    assert a + b == total

circuit = ZKCircuit.from_method(sum_check)

@pytest.mark.parametrize("a,b,total,expected", [
    (3, 7, 10, True),
    (5, 5, 10, True),
    (1, 2, 10, False),
    (0, 0, 0, True),
])
def test_sum_check(a, b, total, expected):
    assert circuit.mock(a, b, total).is_satisfied() == expected
```

## Errors

Compilation errors (unsupported syntax or operations, invalid annotations, loops or
recursion that cannot be bounded) raise `ZinniaException`. A failed assertion is not an
error: it makes the mock result unsatisfied, and no valid proof exists for those inputs.

```python
from zinnia import ZinniaException

try:
    circuit.compile()
except ZinniaException as e:
    print(f"Compilation error: {e}")
```
