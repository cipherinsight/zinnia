# NumPy API

Zinnia compiles a subset of the NumPy API. Inside a circuit, calls of the form `np.<name>`
and array methods such as `x.sum()` are translated into circuit operations that follow
NumPy's semantics (shapes, broadcasting, dtypes and result values).

## Importing NumPy

Write circuits against NumPy as usual:

```python
import numpy as np
```

`from zinnia import np` gives the same module when NumPy is installed. The compiler
recognizes the name `np` in the circuit source, so the circuit body must refer to NumPy
as `np`. Because a circuit is ordinary Python, the same function can also be run with
real NumPy outside Zinnia to compare results.

## Example

```python
import numpy as np
from zinnia import zk_circuit, NDArray, Integer, Float, Public, Private

@zk_circuit
def stats(data: Private[NDArray[Float, 3]],
          expected_mean: Public[Float],
          expected_max: Public[Float]):
    assert np.mean(data) == expected_mean
    assert np.max(data) == expected_max

print(stats(np.array([10.0, 20.0, 30.0]), 20.0, 30.0).is_satisfied())  # True
```

## Supported Functions

The tables below list the `np.*` functions the compiler dispatches. Keyword arguments
follow NumPy's where they are supported. An unsupported function or argument is a
compile-time error.

### Array Creation

| Functions |
|-----------|
| `np.array`, `np.asarray` |
| `np.zeros`, `np.ones`, `np.empty`, `np.full` |
| `np.zeros_like`, `np.ones_like`, `np.empty_like`, `np.full_like` |
| `np.eye`, `np.identity`, `np.diag`, `np.indices` |
| `np.arange`, `np.linspace` |
| `np.copy` |
| NumPy scalar types as constructors and dtypes, e.g. `np.int64(x)`, `np.float64`, `np.bool_` |

### Element-wise Arithmetic

| Functions |
|-----------|
| `np.add`, `np.subtract`, `np.multiply`, `np.divide`, `np.floor_divide` |
| `np.mod`, `np.fmod`, `np.power`, `np.pow` |
| `np.negative`, `np.positive`, `np.abs`, `np.absolute`, `np.fabs`, `np.sign` |
| `np.square`, `np.reciprocal` |
| `np.floor`, `np.ceil`, `np.trunc`, `np.round`, `np.around` |
| `np.minimum`, `np.maximum`, `np.fmin`, `np.fmax`, `np.clip` |

### Transcendental Functions

| Functions |
|-----------|
| `np.sqrt`, `np.exp`, `np.log` |
| `np.sin`, `np.cos`, `np.tan`, `np.arcsin`, `np.arccos`, `np.arctan2` |
| `np.sinh`, `np.cosh`, `np.tanh` |
| `np.deg2rad`, `np.radians`, `np.rad2deg`, `np.degrees` |

The same scalar functions are available under `math` (for example `math.sqrt`), together
with the constants `np.pi`, `np.e`, `math.pi` and `math.e`. These functions operate on
fixed-point `Float` values (see [Real Arithmetic](/docs/data-analytics/real-arithmetic)).

### Comparison and Logic

| Functions |
|-----------|
| `np.equal`, `np.not_equal`, `np.less`, `np.less_equal`, `np.greater`, `np.greater_equal` |
| `np.logical_and`, `np.logical_or`, `np.logical_xor`, `np.logical_not` |
| `np.isclose`, `np.allclose`, `np.array_equal` |
| `np.isin`, `np.in1d` |
| `np.where`, `np.select` |

### Reductions and Statistics

| Functions |
|-----------|
| `np.sum`, `np.prod`, `np.min`, `np.amin`, `np.max`, `np.amax`, `np.any`, `np.all` |
| `np.mean`, `np.var`, `np.std`, `np.median`, `np.percentile` |
| `np.argmax`, `np.argmin` |
| `np.cumsum`, `np.cumprod`, `np.diff` |
| `np.cov`, `np.corrcoef`, `np.histogram`, `np.bincount` |

The following ufunc methods are supported:

- `np.<ufunc>.reduce` for `add`, `multiply`, `minimum`, `maximum`, `logical_or` and
  `logical_and`
- `np.minimum.accumulate` and `np.maximum.accumulate`
- `np.add.reduceat`
- `np.add.outer`, `np.subtract.outer`, `np.multiply.outer` and `np.divide.outer`

### Linear Algebra

| Functions |
|-----------|
| `np.dot`, `np.inner`, `np.outer`, `np.matmul` (and the `@` operator) |
| `np.tensordot`, `np.einsum` |
| `np.linalg.norm` |
| `np.linalg.verify_inverse`, `np.linalg.verify_solve`, `np.linalg.verify_cholesky` |
| `np.correlate`, `np.convolve` |
| `np.triu`, `np.tril` |

`np.linalg.inv`, `np.linalg.solve` and `np.linalg.cholesky` are not compiled. Calling one
is an error that points to the verification functions, which check a result supplied by
the prover (for example `verify_inverse(A, Y)` checks that `Y` is the inverse of `A`).

| `np.flip`, `np.flipud`, `np.fliplr`, `np.rot90`, `np.roll` |
| `np.concatenate`, `np.stack`, `np.vstack`, `np.hstack`, `np.dstack`, `np.column_stack`, `np.row_stack`, `np.block` |

### Writing into Arrays

| Functions |
|-----------|
| `np.copyto`, `np.putmask` |

Ufuncs accept an `out` array, as a keyword or as the positional argument after their
inputs (`np.add(x, 1, y)`).

## Array Methods and Attributes

Arrays support these methods: `sum`, `prod`, `min`, `max`, `any`, `all`, `mean`, `var`,
`std`, `argmax`, `argmin`, `cumsum`, `cumprod`, `reshape`, `flatten`, `ravel`,
`transpose`, `swapaxes`, `moveaxis`, `squeeze`, `repeat`, `clip`, `astype`, `copy`,
`tolist`, `nonzero` and `conjugate`. The attributes `shape`, `ndim`, `size`, `dtype`, `T`,
`flat`, `real` and `imag` are also available.

## Differences from NumPy

- **Bounded shapes.** Every array has a shape known at compile time, or, for a bounded
  dynamic array, a runtime shape within a declared bound (see
  [Bounded Dynamic Arrays](/docs/data-analytics/bounded-dynamic-arrays)).
- **Number representation.** Integer `+`, `-` and `*` are computed exactly in the proof
  system's prime field, so they agree with NumPy's `int64` arithmetic only while no
  overflow occurs. `Float` values are fixed-point numbers with 32 fractional bits, so
  results agree with NumPy's `float64` only up to that precision (see [Real Arithmetic](/docs/data-analytics/real-arithmetic)).
- **Subset of the API.** Only the functions listed above are compiled.
- **Constraint cost.** Every operation adds constraints. Operations that are cheap in NumPy,
  such as sorting or an index computed at runtime, can be comparatively expensive in a
  circuit.
