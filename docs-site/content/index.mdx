# Zinnia

Zinnia compiles Python functions that use NumPy-style array operations into arithmetic circuits for zero-knowledge proofs (zk-SNARKs). You write the computation as an ordinary Python function decorated with `@zk_circuit`, annotate which inputs are public and which are private, and Zinnia produces a circuit that proves the function's assertions hold for the given inputs without revealing the private ones.

## The Problem

A zk-SNARK proves that a fixed arithmetic circuit is satisfied. The circuit is a graph of addition and multiplication gates over a finite field, and its structure must be determined before any input is known. Typical data-analysis code does not have this shape:

1. **Data-dependent control flow.** An `if` statement whose condition depends on a private input cannot select which gates exist, because the circuit must be the same for every input.
2. **Data-dependent array access.** Indexing with a private index, slicing with private bounds, sorting and filtering have no direct counterpart in a fixed circuit.
3. **Variable rebinding.** Python code reassigns variables in different branches. In a circuit, each value is a wire, so the values from both branches must be merged into one.

## The Zinnia Approach

The compiler executes the program symbolically. It unrolls loops, inlines function calls and follows both sides of every branch whose condition depends on an input. Where the two sides assign different values to a variable, it merges them with a selection on the branch condition. An SMT solver (Z3) and a range analysis are used during compilation to decide facts the program does not state directly, for example that a loop condition has become false or that an index is in bounds.

Array operations are kept as whole-array operators in the compiler's intermediate representation (IR) until a dedicated lowering step chooses a circuit construction for each one, such as a permutation check for a sort or a one-hot selection for a read at a private index. The choice depends on the proving backend.

## Key Features

- **Python syntax.** Circuits are Python functions with type annotations such as `int`, `NDArray[int, 10]` or `Float[Array, "2 3"]`.
- **Branch merging.** Variables can be rebound in branches that depend on private inputs. The compiler merges the values at the join point.
- **Bounded dynamic arrays.** `DynamicNDArray[dtype, max_length, max_rank]` describes an array whose length is known only at proving time but has a compile-time upper bound.
- **NumPy array API.** Element-wise arithmetic, matrix multiplication (`@`), reductions, reshaping, slicing, sorting and many `np.*` functions work on circuit arrays. See [NumPy API](/docs/programming-guide/numpy-api) for the list.
- **Fixed-point real numbers.** `float` values are represented in fixed point with 32 fractional bits.
- **Reusable functions.** `@zk_chip` functions are inlined into the circuits that call them, and `@zk_external` functions run in Python while the witness is computed.
- **Proving backends.** A mock backend that checks the constraints without producing a proof, a halo2-base (Halo2-lib) backend that proves in-process, and a Noir backend that emits a Noir program and proves it with `nargo` and `bb`.

## Implementation

Zinnia has a Python front end and a Rust core, built as one Python extension module. The compilation pipeline is:

1. **Front end (Python).** The decorated function's source is parsed with the standard `ast` module, rewritten by a source-level lowering step (for example, `for` loops over `zip` become index loops), and converted into Zinnia's AST format.
2. **IR generation (Rust).** The AST is executed symbolically to produce the IR, a graph of arithmetic, comparison, assertion and array operations.
3. **Optimization.** Passes perform constant folding, dead-code elimination, duplicate-code elimination, removal of assertions that always hold, and related simplifications.
4. **Array lowering.** Each array operator is replaced by a circuit construction chosen for the target backend.
5. **Proving.** The mock, halo2-base or Noir backend evaluates the witness and checks or proves the constraints.
